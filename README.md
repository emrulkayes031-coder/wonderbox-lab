# Wonder Box Lab

The static website for **Wonder Box Lab**, an independent product and technology brand. Games today, with room for apps, AI tools, SaaS, and other software next.

Built as plain HTML, CSS, and JavaScript with a small Node build step. No runtime dependencies, no analytics, no advertising cookies, and no third-party embeds. The site is hosted on **Cloudflare Pages**; GitHub holds the source.

## What is included

- Home page, filterable product catalog, About, Support, and a legal hub
- Dedicated pages for **Tap Defense** and **RushTrail Runaway**
- Privacy policy, terms of use, and a styled 404 page
- Responsive layouts, accessible mobile menu, reduced-motion support, and keyboard-friendly controls
- SEO metadata, JSON-LD, canonical URLs, Open Graph images, sitemap, robots, and a web manifest
- Cloudflare Pages response headers in `src/static/_headers`

The catalog currently lists only real, existing work:

- **Tap Defense** — Android, pre-release. There is no public Google Play listing yet, so the product CTA opens an email instead of pretending to be a download.
- **RushTrail Runaway** — Android, in development. No release date or public download is claimed.

The Apps, AI tools, and SaaS filters intentionally show an honest empty state until those products exist.

## Requirements

- **Node.js 20+** for the build
- **Python 3** for the optional preview server
- **Python 3 with Pillow**, plus the macOS system fonts referenced by the script, only if you want to regenerate the Open Graph images

There is no install step and no `node_modules` dependency.

## Local development

```bash
npm run build     # regenerate the site into dist/
npm run preview   # serve dist/ at http://localhost:4173
```

If port 4173 is busy, use another port:

```bash
python3 -m http.server 4174 --directory dist
# open http://localhost:4174/
```

Optional social-image regeneration:

```bash
npm run og
```

`dist/` is generated and ignored by Git. Cloudflare Pages builds it from source on every deployment.

## Project layout

```text
src/
  build.mjs                 Build into dist/, asset versioning, sitemap, robots, manifest
  data/site.mjs             Site metadata, navigation, categories, contact email, canonical URL
  data/products.mjs         Product facts, copy, screenshots, themes, support and privacy details
  components/icons.mjs      Inline icon set and brand marks
  components/layout.mjs     Document head, header, menu, footer, shared components
  pages/pages.mjs           Page templates and JSON-LD
  assets/css/site.css       Design system and all component styles
  assets/js/site.js         Menu, filters, reveals, copy-email, gallery, FAQ interactions
  assets/fonts/             Self-hosted Instrument Sans and Instrument Serif (with OFL licenses)
  assets/img/               Product screenshots, brand assets, and Open Graph images
  static/_headers           Cloudflare Pages response and cache headers
  og-generate.py            Optional Open Graph image generator
dist/                       Generated by the build — not committed
package.json                Build, preview, and OG scripts
```

Generated HTML should not be edited by hand. Change the source files, then run `npm run build`.

## Editing content

### Site details

Edit `src/data/site.mjs` for the name, contact email, canonical URL, navigation, category descriptions, and principles.

### Products

Edit `src/data/products.mjs`. Each product supplies its category, status, facts, feature copy, screenshots, theme colors, support subject, and privacy information. The build automatically creates:

- the product page under `products/<slug>/`
- the catalog card and home-page feature
- the Support page product card
- the next-product link
- the product entry in `sitemap.xml`

To add a product, add a new object plus its images under `src/assets/img/<slug>/`, then run `npm run build`. Use verified facts only, and link to a store or download page only when a public listing actually exists.

### Pages and styling

- Page copy and JSON-LD: `src/pages/pages.mjs`
- Shared header, footer, and document head: `src/components/layout.mjs`
- Visual system and responsive rules: `src/assets/css/site.css`
- Client interactions: `src/assets/js/site.js`
- Hosting headers: `src/static/_headers`

The build hashes the combined CSS and JavaScript into the asset URLs, so a rebuild busts caches after style or script changes.

## Deployment

### 1. GitHub repository

The source is published as a public repository named **`wonder-box-lab`** under the `emrulkayes031-coder` account. The existing `tap-defense-privacy` repository is not touched.

For reference, the first push was:

```bash
git init
git add .
git commit -m "Build Wonder Box Lab website"
git branch -M main
git remote add origin https://github.com/emrulkayes031-coder/wonder-box-lab.git
git push -u origin main
```

After that, everyday changes are:

```bash
npm run build
git add .
git commit -m "Describe the change"
git push
```

**Do not enable GitHub Pages.** GitHub is the source host only. Cloudflare Pages serves the live site.

### 2. Cloudflare Pages, Git integration

1. Sign in at [dash.cloudflare.com](https://dash.cloudflare.com/) and open **Workers & Pages**.
2. Choose **Create → Pages → Connect to Git**.
3. Authorize Cloudflare for GitHub if prompted, then select the **`wonder-box-lab`** repository.
4. Set the project name to **`wonder-box-lab`** (this produces `wonder-box-lab.pages.dev`).
5. Set the production branch to **`main`**.
6. Use these build settings:
   - **Framework preset:** None
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
7. Leave environment variables empty. If Cloudflare's build image ever lacks a supported Node version, add `NODE_VERSION=20`.
8. Choose **Save and Deploy**.

Cloudflare installs nothing (there are no dependencies), runs the Node build, and publishes `dist/`. Every push to `main` triggers a new production deployment, and pull requests can get their own preview URLs.

The free plan is enough for this site. Check Cloudflare's current limits before relying on a specific build count.

### 3. Custom domain, optional

In the Pages project, open **Custom domains**, add the domain, and follow Cloudflare's DNS instructions. Then update `site.siteUrl` in `src/data/site.mjs`, rebuild, and push. Cloudflare redeploys automatically.

### 4. Verify after the first deploy

- Home, Products, both product pages, About, Support, and the legal pages load
- Unknown URLs show the custom 404 page with working styles and navigation
- `sitemap.xml` and `robots.txt` use the live domain
- Social preview images resolve over HTTPS
- Response headers appear on the live site
- Tap Defense links to `https://emrulkayes031-coder.github.io/tap-defense-privacy/` unchanged

## Secrets and repository hygiene

- `.gitignore` excludes `dist/`, `node_modules/`, environment files, Wrangler state, private keys, credentials, QA screenshots, and OS logs.
- The site has no account system, contact form, analytics, or third-party embeds, so it needs no runtime secrets.
- GitHub authentication is handled by GitHub CLI and the macOS keychain. No token is written into the repository.
- Before publishing, confirm with `git status` and a secret scan that no `.env`, token, key, or local path is staged.

## Accessibility and performance

- Semantic landmarks, a skip link, one `h1` per page, and heading order that follows the page structure
- Keyboard-accessible modal menu with focus return and scroll locking
- Visible focus styles and a reduced-motion path for animation
- Text contrast checked against WCAG AA; the only remaining axe-core flag is the oversized, `aria-hidden` footer wordmark, which is decorative brand lettering and exempt as a logotype
- Self-hosted fonts with `font-display: swap`
- Lazy-loaded screenshots, width/height attributes, and no UI framework or client-side runtime dependency
- Long-lived immutable caching for versioned assets via `_headers`

Tested at 320 px, 390 px, and 1440 px widths, with filter, menu, copy-email, FAQ, gallery, and link checks.
